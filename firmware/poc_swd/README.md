# r5 board test: SWD to an nRF52840 DK (MicroPython)

This is a **board test**, not product firmware. It answers one question: does the r5 hardware connect to a real
target over SWD? It checks every link on the way, so that a failure names the part to look at.

The production firmware will be ESP-IDF/FreeRTOS with DMA-driven SWD (dedicated GPIO / parallel I/O) and CDC-NCM.
Nothing here is meant to be ported, except the stage order and the checks.

- The SWD here is bit-banged with `machine.Pin` at about 30 kHz. That is slow on purpose: it tolerates bad wiring.
- It needs MicroPython v1.29.0 on the board (see `../bringup/README.md`).

## Setup
**r5 board:** channel **A**, the left-hand pair of connectors next to USB-C.
- J301: SWD, 10-pin 1.27 mm.
- J302: UART (not used here).

**nRF52840 DK:**
1. Plug the 10-pin cable into **P18 "Debug in"**, not "Debug out".
2. Line up pin 1 on both ends.
3. Either set **SW6 to "nRF ONLY"**, or power the DK from the nRF USB port with the J-Link USB unplugged.
   Otherwise the onboard J-Link also drives the SWD lines (Nordic DK user guide, "Debug input").
4. Power the DK from USB. Its VDD, and so VTref, is about **3.0 V**.

**Host:** `../../.venv/bin/mpremote`. Create it once with `python3 -m venv .venv && .venv/bin/pip install mpremote`
in the repo root.

## Run
```
./run.sh deploy      # copy device/*.py to the board, then hard-reset it
./run.sh diag A      # staged test; output also goes to logs/diag_A_<time>.log
./run.sh levels A    # snapshot: EN states, line levels, VTref ADC
./run.sh repl        # by hand: import diag; diag.hold_vtref('A') ... diag.release('A')
```

## Unlock and flash the DK (nRF52840 build code F)
```
../../.venv/bin/mpremote connect /dev/ttyACM0 resume exec "import diag; diag.recover('A', really=True)"
../../.venv/bin/mpremote connect /dev/ttyACM0 resume exec "import diag; diag.flash_blinky('A', erase_if_locked=True)"
```
- `recover`:
  - CTRL-AP ERASEALL, **destructive**;
  - UICR.APPROTECT ← HwDisabled;
  - chip identification;
  - **no reset**: build code F re-locks at every reset until firmware writes APPROTECT.DISABLE.
- `flash_blinky`:
  - halts the core;
  - programs `device/nrf_blinky.py` through the NVMC;
  - sets UICR.PSELRESET to P0.18, so pin reset works;
  - resets through the CTRL-AP;
  - reconnects and proves the image runs: APPROTECT still open, LED bits changing in P0.OUT, halt PC inside the
    image;
  - ends with a pin reset.
- `nrf_blinky.py` is generated by `../../.venv/bin/python host/mkblinky.py`. It is a 64-byte hand-assembled Thumb
  image: `APPROTECT->DISABLE = 0x5A`, then an LED1→LED4 chase. The script prints the disassembly (capstone) and checks
  the register writes in an emulator (unicorn). Both tools are in the repo venv.

## What each stage proves
| Stage | Does | Proves | A failure points at |
|---|---|---|---|
| 0 Self-test | All switches open. Reads the pull-up/pull-down levels, toggles the nRESET FET, reads the VTref ADC at 0 V | ESP32 pins, R3xx pulls, Q301 nRESET driver, R316 | the named resistor or FET |
| 1 VTref | Closes EN_VTREF, reads VTref/2 | DUT is powered at 2.8–3.6 V; U302 sw3 works | DK off; cable or pin-1 orientation; U302; GPIO10 (TP305) |
| 2 EN_SWD | Interlocked close. Checks idle levels and **pull probes**: a 45 kΩ internal pull of the opposite sense shows whether the nRF's own pull (≈13 kΩ) on SWCLK/SWDIO/nRESET is on the line | Each wire reaches the DUT through U301 | rotated cable (SWDIO/SWO held low); DK J-Link still active (SWCLK held high); U301 or GPIO9 (TP306) |
| 3 nRESET | 20 ms reset pulse through to the DUT, measures the release rise time | Reset path end to end: the DK app restarts, watch its LEDs | DUT holding reset; Q301 |
| 4 SWD link | JTAG-to-SWD, reads DPIDR at three speeds, then 50 re-reads | SWCLK and SWDIO, protocol timing | the hint printed for the ACK pattern seen |
| 5 Debug ports | Debug power-up, AP0/AP1 IDR, CTRL-AP APPROTECTSTATUS | DAP works, target is an nRF52 | APPROTECT: `diag.recover('A', really=True)` **erases the chip** |
| 6 Memory | AHB-AP reads (CPUID, FICR part/variant/IDs, UICR, vector table), halt → read PC → resume | Full debug access: the base for flashing | |
| 7 Disconnect | Debug power-down, pin reset (nRF leaves debug mode), opens EN_SWD, then EN_VTREF | Safe state restored | |

Every run ends in the safe state (stage 7 runs in `finally`): all switches open, reset released.

## Known limits
- **3.3 V into a 3.0 V target.**
  - r5 has no level translation, so the tool's highs reach the DK at 3.3 V. That is VDD + 0.3 V, the nRF52840's
    absolute maximum.
  - Stage 1 warns about it. The test runs with the weakest drive (DRIVE_0) and the 33 Ω series resistors, so
    clamp current stays small.
  - For production, run the DUTs at 3.3 V or add VTref-tracking I/O in rev E.
- **Pull probes are heuristic.** They compare 45 kΩ against 100 kΩ, which lands between the ESP32 input
  thresholds. The test therefore records a baseline with the switches open and reports only a *change*.
- **Never soft-reset this board.**
  - On 2026-11-06 MicroPython's soft reset hung the ESP32-S3 native USB twice: once right after a soft reset,
    once while rebooting. Only a USB replug recovered it; Ctrl-C and the 1200-baud reboot did not reach it.
  - There are open upstream reports of USB trouble after soft reset on the ESP32-S3.
  - `run.sh` runs every mpremote command with `resume`, so nothing soft-resets on connect. `deploy` gets a fresh
    interpreter from `machine.reset()` (a hard reset, the same path as plugging in).
  - Do not press Ctrl-D in `./run.sh repl`.

## Files
| File | Content |
|---|---|
| `device/r5.py` | r5 pin map, `safe_all()`, `Channel` (VTref ADC, interlocked EN_SWD close, line probes) |
| `device/swd.py` | ADIv5 SWD host: packets, DP/AP, MEM-AP read32/write32 |
| `device/nrf52.py` | nRF52840 IDs, FICR/UICR tables, halt test, CTRL-AP ERASEALL/reset, NVMC erase/program |
| `device/nrf_blinky.py` | generated test image (16 words) |
| `host/mkblinky.py` | assembles, disassembles and emulates the test image; writes `device/nrf_blinky.py` |
| `device/diag.py` | the staged test plus helpers (`levels`, `hold_vtref`, `release`, `recover`, `flash_blinky`) |
| `device/boot.py` | `r5.safe_all()` on every boot |
| `device/main.py` | heartbeat: the LED flashes for 100 ms every second; the REPL stays free |
| `run.sh` | host wrapper around mpremote |
| `logs/` | diagnostic run logs |

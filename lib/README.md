# esp-swd library (`lib/`)

Portable C11 core of esp-swd. It has no RTOS, no vendor headers and no dynamic allocation. Hardware is reached only
through op tables supplied by a port or board. The design is in `../docs/firmware-architecture.md`. MIT licence (`../LICENSE`).

| Part | Files | What it does |
|---|---|---|
| SWD PHY | `include/esw/swd_phy.h` | Packet-level interface. A port can replace the bit-bang engine with a fast one |
| Bit-bang engine | `core/swd/swd_bitbang.c` | Portable SWD over four pin operations (same timing as the r5 board test) |
| ADIv5 | `core/swd/adiv5.c` | Connect, DP/AP access, power-up, sticky-error handling, MEM-AP single and block (1 KB TAR boundaries, pipelined reads) |
| Core control | `include/esw/cpu.h`, `core/cpu/cortexm.c` | Architecture-neutral halt, resume, registers, call setup, reset. Cortex-M first |
| CRC verify loader | `core/loader/crc32_loader.c`, `crc32_blob.inc` (generated by `loaders/crc32/build.py`) | Built-in on-target CRC-32 for any Cortex-M; the module only supplies 4 KB of scratch RAM |
| Loader runtime | `include/esw/loader.h`, `core/loader/loader.c` | Generic RAM loaders for any chip: download and verify, call ABI (FLM-style, returns to a BKPT trap), streaming ABI (mailbox + buffer ring, the core keeps running) |
| Target interface | `include/esw/target.h`, `core/target/target.c` | Module interface, registry, routing per memory region (direct or loader), verify (read-back, or CRC on the target) |
| Target modules | `targets/<name>/`, `targets/registry.c` | Chip and family support. Now: `nrf52`, `nrf53` (nRF5340, two cores), `stm32u5`, and `generic` (any Cortex-M, registered last) |
| Channel | `include/esw/channel.h`, `channel/channel.c` | Isolation interlock: VTref first, holders, VTref-loss and host-loss handling; inhibit (switch mode "off") and the host pin holder (mode "on") |

## Build and test on a PC
```
python3 -m venv .venv && .venv/bin/pip install cmake ninja      # once, in the repo root
PATH=$PWD/.venv/bin:$PATH
cmake -S . -B build -G Ninja && cmake --build build && ctest --test-dir build --output-on-failure
cmake -S . -B build-asan -G Ninja -DESW_SANITIZE=ON && cmake --build build-asan && ctest --test-dir build-asan
```
- The tests run against `tests/sim/`, a bit-level SWD target simulator of an nRF52840-like chip.
  - It models the wire protocol, DP lock-out and sticky flags, posted reads, a 1 KB TAR wrap, CTRL-AP/APPROTECT
    including the build-code-F re-lock on reset, and NVMC semantics.
  - It can run C functions in place of loader code. This includes a resident streaming loader and an external-flash
    region that only a loader can reach.
- The simulator also counts SWDIO bus contention; tests assert it stays at zero.

## Adding a chip or family module
1. Write `targets/<name>/<name>.c`, implementing `esw_target_driver_t`:
   - `probe`: is it this chip? Check DPIDR and AP IDRs;
   - `attach`: identify it and add memory regions;
   - `unlock`;
   - `erase` and `program`, for direct regions;
   - `reset`;
   - `detach`.
2. Write `include/esw/targets/<name>.h`, exporting `extern const esw_target_driver_t esw_target_<name>;`.
3. Add one `#ifdef ESW_TARGET_<NAME>` line to `targets/registry.c` (before `generic`, which must stay last), then
   build with `-DESW_TARGETS="nrf52;<name>;generic"`.
   - Multi-core parts: `t->core` holds the requested core (`esw_target_detect_core`); a single-core module returns
     `ESW_ERR_ARG` for any core but 0. `ESW_TARGET_CORE_RAW` skips the chip modules (diagnosis, bring-up).
   - Leave the part as found: undo debug settings in `detach` (e.g. watchdog freeze bits, a released core).
   - A region served by a RAM loader: the optional `loader_prepare` hook runs before the loader is downloaded
     (STM32U5: reset-halt once, core clock up). A streaming loader's `program` returns once the data is handed
     over; `esw_target_sync` waits for it and reports a failed buffer (commands, verify and finish sync first).
     Loader sources live in `loaders/<name>/`, each with a `build.py` that verifies the blob in an emulator and
     writes a checked-in `.inc`, so the library build never needs an Arm compiler.
4. For memories the debugger cannot write directly (for example external OSPI flash), add a region with an
   `esw_loader_desc_t` in `attach`. The common loader runtime then does download, execution and streaming; the module
   writes no transport code.
5. Add a test under `tests/`, against the simulator or an extended copy of it.
